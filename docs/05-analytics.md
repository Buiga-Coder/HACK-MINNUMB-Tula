# Методики расчёта и ограничения интерпретации

Версия 1.0. Все приведённые пороги и численные примеры — проектные. Они не являются нормативами Тульской области. До согласования слой должен иметь маркировку «Демонстрационная методика» либо быть отключён в промышленном контуре.

## 1. Пешие изохроны

Вход: публичные входы ОКС, версия пешеходного графа, разрешённые направления/переходы, профиль walking, выбранные интервалы 300–1800 секунд с шагом 60 секунд, текущий или утверждённый проектный сценарий.

Базовая скорость v = 4,8 км/ч = 1,333… м/с. Вес ребра t = длина_в_метрах / v + согласованные задержки. Закрытые участки исключаются; автомобильные дороги без пешеходного доступа не включаются. Задержки на переходах и лестницах — отдельные параметры версии, а не скрытые постоянные.

Алгоритм: привязать вход к допустимому ребру; учесть стоимость подхода; найти доступную часть графа в пределах времени; построить полигон охвата, сохраняющий крупные непроходимые барьеры; объединить зоны нескольких публичных входов. Нельзя применять выпуклую оболочку, которая показывает недоступный берег доступным только потому, что он внутри оболочки.

Максимальная автоматическая привязка к графу — 100 м как проектное значение. Привязка через реку/забор без прохода запрещена даже при меньшем расстоянии. При невозможности — ошибка, ручная проверка входа. Вложенность зоны 10 минут в 15 минут обязательна с учётом согласованной геометрической погрешности.

Для будущего объекта публиковать «Прогноз после открытия по текущей дорожной сети». Если доступность основана на проектном проходе, показывать его отдельно и указывать источник. Не обещать, что будущая сеть уже существует.

Контроль: синтетический граф с известными временами, река без моста, мост, закрытый двор, несколько входов, изолированный участок. Экспертная выборка не менее 10 реальных ОКС после получения данных; причины отклонений фиксируются.

## 2. Социальная обеспеченность: единицы и знаменатель

Для территории m и отраслевого показателя s:

- C — действующая мощность, выраженная в одной утверждённой единице;
- P — целевая численность населения той же территории и сопоставимого периода;
- N — утверждённая норма мощности на 1000 человек соответствующей группы;
- D = P × N / 1000 — нормативная потребность;
- K = C / D — коэффициент обеспеченности при D > 0.

Проектная шкала: K < 0,90 — пониженная, красный; 0,90 ≤ K ≤ 1,10 — нормальная, зелёный; K > 1,10 — повышенная, жёлтый. Нет подходящей нормы, населения, мощности или сопоставимого периода — серый no_data. P=0 не означает бесконечную обеспеченность; результат не рассчитывается. Достоверные C=0 при D>0 дают K=0.

Пример только для теста: P=10 000, N=80 мест/1000 человек, C=640 мест. D=800, K=0,80, категория low. При C=720 граница normal; C=880 ещё normal; C=881 — high.

Для детских садов и школ определить соответствующие возрастные группы и раздельные нормы. Посещения поликлиники в смену нельзя складывать с койками. Для спорта и культуры требуются собственные единицы и нормы. Для энергетики сначала согласовать показатель: доступная мощность, дефицит мощности, надёжность или иная величина. Если знаменатель не население, использовать отдельную методику и название шкалы.

## 3. Территориальное распределение и сценарии

Базовый муниципальный расчёт включает учреждения по закреплённой территории/назначению. Положение точки не всегда отражает территорию обслуживания; исключения фиксируются. Дубли учреждений и мощности разных очередей строительства устраняются по устойчивым ID и датам действия.

Для микрорайонов нужны границы, целевое население и правило распределения мощности. Если одно учреждение обслуживает несколько территорий, доли мощности должны суммироваться до 1 и иметь обоснование. Муниципальный итог нельзя механически копировать во все микрорайоны.

Плотность населения = население / площадь территории в км². Это дополнительный показатель, а не заменитель отраслевой потребности. Для расчёта площади использовать метрическую проекцию или геодезические функции.

Данные операторов используются только в агрегированном и разрешённом виде; описываются период наблюдения, покрытие, поправки и тип населения. Перепись характеризует иной период и метод наблюдения. Их объединение допускается после утверждения методики; нельзя выдавать число устройств за число жителей без модели.

Прогноз: C_future = C_current + новые мощности − подтверждённые выводимые мощности. Если новый ОКС заменяет старое учреждение, учитывать прирост, а не двойную полную мощность. P_future либо прогнозное население с источником, либо P_current с явной подписью «Численность населения не меняется». Предполагаемый ввод не обновляет базовый слой автоматически.

## 4. Удовлетворённость ответами

Единица наблюдения — оценка гражданином конкретного ответа на обращение. Для каждой оценки нужны устойчивый обезличенный ID ответа, отрасль, территория проблемы, дата ответа, дата оценки, шкала и значение. Контактные данные не входят в аналитический набор.

Основной индекс для бинарной шкалы: S = 100 × N_positive / N_rated. Для шкалы 1–5 проектный маппинг: 4–5 — положительно, 1–3 — не положительно; он требует утверждения и раскрытия в интерфейсе. Несовместимые шкалы не смешиваются без явного преобразования.

В период включаются ответы по дате ответа. Оценки учитываются по состоянию на указанную дату расчёта; поздняя оценка создаёт новую версию агрегата. Одна действующая оценка на ответ: при изменении использовать последнюю допустимую. N_eligible — ответы за тот же период, для которых оценивание было доступно; Participation = 100 × N_rated / N_eligible. При N_eligible=0 доля null, а не 0%.

Пример: 40 ответов доступны для оценки, 20 оценены, 15 оценок положительные. S=75%, участие=50%. Этот индекс характеризует оценивших граждан и не объявляется мнением всех жителей.

Проектная цветовая шкала: S < 50% — низкая, 50% ≤ S < 80% — средняя, S ≥ 80% — высокая. При N_rated < 10 — недостаточно данных, серый; точные счётчики малой группы не выдаются. Нулевое число обращений не означает 100% удовлетворённости.

Фильтры ограничиваются утверждёнными отраслями, периодами и уровнями территории. Публиковать фиксированные месячные/квартальные агрегаты либо безопасные их объединения. Произвольные диапазоны API принимаются только если составляют разрешённые агрегаты; иначе 422. Проверять возможность восстановления подавленной ячейки вычитанием из итогов: при риске применять дополнительное подавление итогов/соседних ячеек. Простого скрытия подписи на карте недостаточно.

## 5. Проверяемость

Каждый слой публикует run_id, версии входных данных, границ и методики, время расчёта, качество и список ограничений. Повторный расчёт на одинаковом наборе воспроизводит числа и категории. Промежуточные значения считаются без преждевременного округления; категория определяется по неокруглённому коэффициенту, экранные значения округляются отдельно и поясняются на границах.

Демонстрационная аналитика не смешивается с реальной даже внутри одной территории. Если реальная исходная выборка отсутствует, демонстрационный слой отделён переключателем и водяной меткой.

## Отображение в HTML-демо

Ползунок 5–30 минут управляет демонстрационными зонами по прямому расстоянию
(80 м/мин): границы через 5 минут и дополнительная граница выбранного времени.
Зоны окрашены от зелёного к красному. Это интерфейсная демонстрация, не реализация
сетевого расчёта FR-14; дороги, переходы и препятствия не учитываются.

Слой оценок отображается мягкой заливкой геометрии муниципалитета. Значение —
среднее доступных тестовых `satisfaction` объектов данной территории. Пропуски
не заменяются нулём, муниципалитет без оценок остаётся белым. Цветовая шкала
от красного (0%) через жёлтый (50%) к зелёному (100%), значение и количество
демо-объектов доступны в подсказке. Эти средние не являются реальной
удовлетворённостью ответами и не заменяют промышленную методику раздела 4.
Растушёвка — визуальный эффект, не интерполяция оценок на соседние территории.
