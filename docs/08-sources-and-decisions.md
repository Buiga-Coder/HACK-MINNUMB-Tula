Прямые ссылки закупок взяты из задания; промежуточные vk.ru/away.php не используются как интеграционные адреса. Отказ веб-загрузки не означает, что источник не работает для пользователей. GitHub через веб-проверку не открылся, однако Git-доступ оказался доступен.

Правовые реквизиты, обязательные сроки обработки обращений и состав требований к государственным системам здесь не объявляются установленными. Их определяет оператор с ответственными специалистами после уточнения статуса системы и состава данных; это входное условие промышленной реализации, а не задача демонстрационного слоя.

## 2. Принятые проектные решения

| ID | Решение | Причина |
|---|---|---|
| ADR-01 | Введённые объекты по умолчанию, активные отдельным режимом | Согласование названия проекта и требований по стройкам |
| ADR-02 | Модульный монолит и отдельные workers | Единая модель публикации и управляемая эксплуатация на старте |
| ADR-03 | Реальная сетевая изохрона, без замены кругом | Пешая доступность зависит от проходов и препятствий |
| ADR-04 | Отдельные текущий и прогнозный слои | Плановая мощность/рендер не являются текущим фактом |
| ADR-05 | Серый для отсутствующих или подавленных данных | Неизвестность нельзя представлять нулём или нормой |
| ADR-06 | Базовая жалоба через официальную форму; API условный | Нет подтверждённого двустороннего доступа |
| ADR-07 | Демо отделено от реальных сведений | Нельзя приписывать вымышленные показатели реальным объектам |
| ADR-08 | Оценки ответов, а не число жалоб | Количество сообщений не измеряет удовлетворённость |
| ADR-09 | Схема исходного приложения остаётся открытой | Само приложение не предоставлено |

Изменение решения фиксируется новой записью: дата, автор, основание, затронутые требования и тесты. Открытый вопрос не превращается в согласованное решение только потому, что прошёл срок.

## 4. Подтверждение документации

Текущий комплект покрывает описание пользователя, но ещё не согласован менторами/заказчиком. Для утверждения записываются версия, дата, перечень исключений, ответственные и решение. Изменения после утверждения проходят оценку влияния на срок, данные, API и тесты.
